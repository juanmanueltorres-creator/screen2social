# Screen2Social V0.3 Social Package Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extend `screen2social process <video>` so every successful package contains deterministic `post.md` alongside `linkedin.mp4`, `thumbnail.png`, and `metadata.json`, while preserving all V0.1/V0.2 safety and CLI contracts.

**Architecture:** Add one focused standard-library module, `screen2social.social`, that renders and writes the Markdown template. Keep `process_recording()` as the orchestrator: create the existing `ready/<slug>/` directory, build media, write metadata, write `post.md`, and return a `ProcessResult` that exposes all four artifacts. No new CLI command, dependency, publishing integration, transcription, or OBS behavior is introduced.

**Tech Stack:** Python 3.11+, standard library (`pathlib`), pytest, existing FFmpeg/ffprobe integration, existing GitHub Actions workflow.

**Spec:** `docs/superpowers/specs/2026-08-28-v0.3-social-package-design.md`

## Global Constraints

- Start implementation from `feat/v0.3-social-package`, based on Screen2Social `0.2.0`.
- Keep the canonical package path exactly `ready/<slug>/` using the existing `slugify()` / `create_package_dir()` behavior.
- Preserve fail-closed `OUTPUT_EXISTS`; never append timestamps, counters, UUIDs, or overwrite existing packages.
- Preserve source recordings; never edit, move, or delete the source.
- Keep CLI success output exactly `READY: <package_dir>` with no extra stdout.
- Use one built-in LinkedIn-oriented Markdown template; no Jinja2 and no custom template-file system.
- Do not generate post copy, hashtags, topics, handles, or descriptions with AI.
- Do not add Whisper, subtitles, silence editing, Auto-Editor, automatic `stop -> process`, social APIs, browser automation, Postiz, scheduler, GUI, backend, or database.
- Keep OBS `status`, `record`, and `stop` untouched unless a regression test reveals an accidental break.
- Keep package/runtime version at `0.2.0` throughout feature implementation and smoke. Bump to `0.3.0` only at the separate release gate after the feature is reviewed, smoke-tested, merged with explicit human approval, and `main` is verified.
- Every production behavior change follows RED -> verify RED -> minimal GREEN -> verify GREEN -> commit.

def build_post_markdown(source: Path) -> str:
    title = source.stem.strip() or "Recording"

        "## Post\n"
        "\n"

        "## Assets\n"

        "- [ ] Revisé el texto\n"
        "- [ ] Publicado en LinkedIn\n"
    )


def write_post(path: Path, content: str) -> None:

    synthetic_video, tmp_path, monkeypatch

        raise OSError("disk full")

        process_recording(
            synthetic_video,
            ready_root=ready,
            toolchain=discover_toolchain(),
        )

    assert exc.value.code == "PROCESSING_FAILED"
    assert synthetic_video.is_file()
    assert not (ready / "source").exists()
