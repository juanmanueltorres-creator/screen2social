# Screen2Social V0.2 — OBS Control Design

Status: approved in chat, written-spec review pending
Date: 2026-08-28
Branch: `feat/v0.2-obs-control`
Base: `main` @ `a0376d8dc0e51d6613dfe3142e604a2ea4d64174`

## 1. Purpose

V0.2 adds a small, local OBS control subsystem to Screen2Social without changing the proven V0.1 media-processing contract.

V0.1 remains responsible for:

```text
recording file
-> linkedin.mp4
-> thumbnail.png
-> metadata.json
```

V0.2 adds only:

```text
OBS Studio
-> status
-> start recording
-> stop recording
-> return saved recording path
```

Automatic `stop -> process_recording()` chaining is explicitly deferred until the real Windows/OBS smoke test proves that the returned recording path is reliable in the user's OBS configuration.

## 2. Dependency decision

Use `simpleobsws` 1.4.3 as the OBS client adapter.

Rationale:

- Python async client for obs-websocket 5.x;
- current PyPI release at design time: 1.4.3;
- MIT licensed at design time, compatible with this repository's MIT license;
- exposes the minimal primitives V0.2 needs: connect, identify, call, disconnect;
- avoids implementing the obs-websocket authentication/protocol handshake ourselves.

V0.2 will pin the runtime dependency to:

```text
simpleobsws==1.4.3
```

Do not use `obsws-python` in V0.2.

## 3. OBS compatibility contract

Supported target:

- OBS Studio 28+;
- obs-websocket 5.x;
- default endpoint `ws://localhost:4455`;
- authentication enabled;
- password supplied only through environment configuration.

The relevant OBS requests are:

```text
GetRecordStatus
StartRecord
StopRecord
```

`StopRecord` must return `outputPath`; Screen2Social exposes that path but does not process it automatically in V0.2.

## 4. Security and configuration model

V0.2 is local-first and fail-closed.

Exact defaults:

```text
host = localhost
port = 4455
timeout_seconds = 5.0
```

Required environment variable:

```text
SCREEN2SOCIAL_OBS_PASSWORD
```

Optional environment variables:

```text
SCREEN2SOCIAL_OBS_HOST
SCREEN2SOCIAL_OBS_PORT
SCREEN2SOCIAL_OBS_TIMEOUT_SECONDS
```

Validation contract:

- host must be non-empty after trimming;
- port must parse as an integer from 1 through 65535;
- password must be non-empty;
- timeout must parse as a finite positive float greater than 0;
- invalid configuration fails before creating a WebSocket client.

Rules:

- password is never accepted as a CLI argument;
- password is never printed, logged, stored in metadata, or committed;
- `.env.example` documents variable names but contains no secret;
- V0.2 reads `os.environ` directly and does not add `python-dotenv`;
- copying `.env.example` to `.env` alone does not load it; README must show PowerShell environment-variable setup explicitly;
- the repository's existing `.env` ignore remains in force;
- V0.2 requires authenticated OBS WebSocket operation by design;
- V0.2 does not expose OBS to the public Internet or configure tunnels/port-forwarding.

If `SCREEN2SOCIAL_OBS_PASSWORD` is missing or empty, the command fails before attempting a connection with `OBS_CONFIG_ERROR`.

## 5. Architecture

```text
CLI
 |
 v
obs.py sync facade
 |
 | asyncio.run(...)
 v
async SimpleOBS adapter
 |
 v
simpleobsws 1.4.3
 |
 v
ws://localhost:4455
 |
 v
OBS Studio
```

The asynchronous dependency is contained inside the OBS module. Existing V0.1 media modules remain synchronous and unchanged.

One CLI invocation opens one OBS connection, performs one operation, and disconnects in `finally` cleanup.

## 6. New module boundary

Create:

```text
src/screen2social/obs.py
```

This module owns:

- OBS configuration loading/validation;
- construction of the WebSocket URL;
- connection + identification;
- OBS request execution;
- response normalization;
- OBS-specific error mapping;
- guaranteed disconnect cleanup;
- synchronous facade functions for the existing CLI.

It must not:

- import `package.py`;
- call `process_recording()`;
- know about LinkedIn presets;
- publish to social networks;
- edit media files.

## 7. Stable V0.2 data contracts

```python
@dataclass(frozen=True)
class ObsConfig:
    host: str
    port: int
    password: str
    timeout_seconds: float


@dataclass(frozen=True)
class ObsRecordStatus:
    active: bool
    paused: bool
    timecode: str
    duration_ms: int
    bytes_written: int


@dataclass(frozen=True)
class ObsStopResult:
    output_path: Path
```

Public synchronous facade:

```python
def load_obs_config(environ: Mapping[str, str] | None = None) -> ObsConfig: ...
def get_record_status(config: ObsConfig | None = None) -> ObsRecordStatus: ...
def start_recording(config: ObsConfig | None = None) -> None: ...
def stop_recording(config: ObsConfig | None = None) -> ObsStopResult: ...
```

The async/simpleobsws implementation remains internal.

## 8. CLI contract

Existing commands remain unchanged:

```text
screen2social --version
screen2social doctor
screen2social process <video> [--ready-dir PATH]
```

Add:

```text
screen2social status
screen2social record
screen2social stop
```

Expected user-facing output shapes:

### `status`

Stopped:

```text
OBS: connected
Recording: stopped
```

Active:

```text
OBS: connected
Recording: active
Timecode: 00:01:23.456
```

Paused may be reported explicitly when OBS returns `outputPaused=true`.

### `record`

```text
RECORDING: started
```

### `stop`

```text
RECORDING: stopped
FILE: C:\path\to\recording.mkv
```

The password must never appear in output, even on errors.

## 9. Error contract

Extend `errors.py` with OBS-specific stable errors/codes.

Required codes:

```text
OBS_CONFIG_ERROR
OBS_CONNECTION_FAILED
OBS_AUTH_FAILED
OBS_ALREADY_RECORDING
OBS_NOT_RECORDING
OBS_REQUEST_FAILED
```

Mapping rules:

- missing/invalid environment configuration -> `OBS_CONFIG_ERROR`;
- socket/DNS/refused/timeout before successful identification -> `OBS_CONNECTION_FAILED`;
- obs-websocket close code `4009` during identification -> `OBS_AUTH_FAILED`;
- `StartRecord` request status code `500` (`OutputRunning`) -> `OBS_ALREADY_RECORDING`;
- `StopRecord` request status code `501` (`OutputNotRunning`) -> `OBS_NOT_RECORDING`;
- any other failed OBS request -> `OBS_REQUEST_FAILED`.

Unexpected low-level exceptions must not leak a traceback through normal CLI execution. The CLI prints the stable code plus a safe message and returns non-zero.

## 10. Connection lifecycle

Each operation follows this lifecycle:

```text
load config
-> construct client
-> connect
-> wait_until_identified(timeout_seconds)
-> call one OBS request with timeout_seconds
-> validate RequestResponse.ok()
-> normalize response
-> disconnect in finally
```

A connection that succeeds at TCP/WebSocket level but fails identification must not be reported as connected.

No automatic retries in V0.2. A retry policy would hide configuration errors and is not needed for a local CLI.

## 11. Request normalization

### GetRecordStatus

Normalize OBS fields:

```text
outputActive   -> active
outputPaused   -> paused
outputTimecode -> timecode
outputDuration -> duration_ms
outputBytes    -> bytes_written
```

Required types after normalization:

```text
active        bool
paused        bool
timecode      str
duration_ms   int >= 0
bytes_written int >= 0
```

Missing, negative numeric, or malformed required fields produce `OBS_REQUEST_FAILED`.

### StartRecord

Success returns no domain payload.

Request status `500` maps to `OBS_ALREADY_RECORDING`.

### StopRecord

Require response field:

```text
outputPath
```

Normalize it to `Path` and return `ObsStopResult`.

Request status `501` maps to `OBS_NOT_RECORDING`.

An empty/missing/non-string `outputPath` produces `OBS_REQUEST_FAILED`.

V0.2 does not require the path to exist inside the adapter because OBS may still be finalizing the file immediately after the stop response; existence is verified by the real-machine smoke gate before merge.

## 12. Testing strategy

CI must not require OBS Studio.

Create focused tests around a fake/injected simpleobsws-compatible client factory.

Test categories:

### Configuration

- defaults are `localhost`, `4455`, `5.0`;
- password required;
- empty host rejected;
- port outside 1..65535 rejected;
- invalid/non-positive/non-finite timeout rejected;
- secret never included in repr/error text where controllable.

### Connection

- successful connect + identify;
- connection refused -> `OBS_CONNECTION_FAILED`;
- identify timeout -> `OBS_CONNECTION_FAILED`;
- authentication close code 4009 -> `OBS_AUTH_FAILED`;
- disconnect runs after success and failure.

### Status

- stopped response normalization;
- active response normalization;
- paused response normalization;
- malformed response -> `OBS_REQUEST_FAILED`.

### Record

- StartRecord success;
- status code 500 -> `OBS_ALREADY_RECORDING`.

### Stop

- StopRecord success returns exact `Path`;
- status code 501 -> `OBS_NOT_RECORDING`;
- missing/invalid outputPath -> `OBS_REQUEST_FAILED`.

### CLI

- new parser commands exist;
- stable success output;
- stable error code + non-zero exit;
- existing `process` and `doctor` tests remain green.

All 19 V0.1 tests remain regression requirements.

## 13. Real-machine smoke gate

CI proves adapter behavior with fakes, but cannot prove communication with the user's local OBS instance.

V0.2 is not considered fully validated until a Windows smoke test is performed with OBS open and WebSocket authentication enabled:

```text
screen2social status
screen2social record
<record a few seconds>
screen2social status
screen2social stop
```

Acceptance evidence:

- `status` connects and reflects stopped state;
- `record` starts OBS recording;
- second status reflects active state;
- `stop` stops recording;
- returned `FILE:` path exists locally after OBS finishes the stop operation;
- the created file is readable by `screen2social process <path>` as a separate manual command.

The last step validates interoperability without coupling V0.2 to V0.1.

## 16. V0.2 acceptance gate

V0.2 may be proposed for merge only when:

```text
[ ] simpleobsws 1.4.3 is the only new runtime dependency
[ ] all 19 V0.1 tests remain green
[ ] new OBS tests are green
[ ] no real OBS instance is required by CI
[ ] status command works against fake adapter in tests
[ ] record command works against fake adapter in tests
[ ] stop returns normalized output path in tests
[ ] auth failure maps to OBS_AUTH_FAILED
[ ] refused/unreachable OBS maps to OBS_CONNECTION_FAILED
[ ] already recording maps to OBS_ALREADY_RECORDING
[ ] not recording maps to OBS_NOT_RECORDING
[ ] malformed request responses map to OBS_REQUEST_FAILED
[ ] password never appears in CLI output/tests/docs examples as a real secret
[ ] README explains Windows OBS WebSocket + PowerShell env setup
[ ] GitHub Actions passes
[ ] real Windows/OBS smoke test returns an existing recording path
[ ] manual `screen2social process <returned-path>` succeeds
```
