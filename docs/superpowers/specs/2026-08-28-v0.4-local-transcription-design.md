# Screen2Social V0.4 — Local Transcription Design

Date: 2026-08-28
Status: design approved in chat; implementation not started
Repository: `juanmanueltorres-creator/screen2social`
Base: `main` at `a3059bafb841c3606f664d9870fec0dba1d319d9`
Feature branch: `feat/v0.4-local-transcription`

## 1. Goal

V0.4 adds optional, fully local transcription to the existing Screen2Social processing pipeline.

The user-facing flow becomes:

```powershell
screen2social process demo.mkv --transcribe
```

A successful transcription-enabled package contains:

```text
ready/demo/
├── linkedin.mp4
├── thumbnail.png
├── metadata.json
├── post.md
├── transcript.txt
└── transcript.srt
```

Without `--transcribe`, V0.3 behavior remains unchanged:

```text
ready/demo/
├── linkedin.mp4
├── thumbnail.png
├── metadata.json
└── post.md
```

The feature is local-first, free to run, explicit, fail-closed, and does not publish or modify the source recording.

## 2. Product decisions

The following decisions are approved and normative for V0.4:

1. Transcription is opt-in through `screen2social process <video> --transcribe`.
2. V0.4 produces both `transcript.txt` and `transcript.srt`.
3. The transcription engine is `whisper.cpp` through its `whisper-cli` executable.
4. `whisper-cli` and the model are installed and managed outside Screen2Social.
5. Screen2Social performs no model or binary downloads.
6. Configuration uses environment variables, not new CLI flags.
7. Language is fixed to `auto` for V0.4.
8. If transcription was explicitly requested and any transcription step fails, the package is not delivered.
9. Temporary audio is deleted and never belongs to a successful package.
10. No subtitles are burned into the video.
11. V0.4 does not cut silence or otherwise edit video content beyond the existing LinkedIn transcode.
12. The feature V0.4 is implemented and validated first; the package version bump to `0.4.0` remains a separate release gate after feature merge.

## 3. Architecture

V0.4 introduces a dedicated transcription subsystem rather than extending the mandatory media toolchain.

```text
OBS control       -> obs.py
FFmpeg/media      -> media.py
social template   -> social.py
transcription     -> transcription.py
package orchestration -> package.py
CLI               -> cli.py
```

The new module is:

```text
src/screen2social/transcription.py
```

This module owns:

- transcription configuration discovery;
- validation of `whisper-cli` and model paths;
- construction and execution of the temporary-audio extraction step;
- construction and execution of the `whisper-cli` command;
- verification that the expected TXT and SRT outputs exist;
- cleanup of transcription-specific temporary artifacts;
- mapping low-level failures into stable Screen2Social errors.

`media.py` remains responsible for the mandatory FFmpeg/ffprobe media pipeline. `obs.py` remains independent of transcription. `package.py` coordinates the feature but does not contain Whisper-specific subprocess details.

## 4. Configuration contract

Whisper configuration is read only when transcription is requested.

Required environment variables:

```text
SCREEN2SOCIAL_WHISPER_CLI
SCREEN2SOCIAL_WHISPER_MODEL
```

Example on Windows:

```powershell
$env:SCREEN2SOCIAL_WHISPER_CLI = "C:\tools\whisper.cpp\whisper-cli.exe"
$env:SCREEN2SOCIAL_WHISPER_MODEL = "C:\models\ggml-base.bin"
```

Screen2Social must not download, clone, install, update, or otherwise manage either resource.

A normal invocation without `--transcribe` must not require or inspect these variables:

```powershell
screen2social process demo.mkv
```

No `--model`, `--language`, or `--whisper-path` flags are added in V0.4.

## 5. Transcription configuration type

`transcription.py` should expose a small immutable configuration object, conceptually:

```python
@dataclass(frozen=True)
class TranscriptionToolchain:
    whisper_cli: Path
    model_path: Path
```

The exact function names are implementation details, but configuration discovery must be independently testable and must reject missing or invalid resources before package creation when possible.

## 6. Input audio requirement

Transcription requires an audio stream.

The existing source media probe already records `audio_codec: str | None`. The orchestrator should use this authoritative probe result rather than probing the source a second time solely to determine whether audio exists.

When `--transcribe` is requested and the source has no audio stream, processing fails with `TRANSCRIPTION_NO_AUDIO` before `ready/<slug>/` is created.

Without `--transcribe`, a source without audio keeps the existing V0.3 behavior.

## 7. Temporary audio

`whisper-cli` receives a deterministic temporary WAV extracted using the already-required FFmpeg binary.

Conceptual output path:

```text
ready/<slug>/.transcription.wav
```

Required audio properties:

```text
mono
16 kHz
PCM signed 16-bit
WAV container
```

The extraction command must be built as an argument list and executed without a shell.

The temporary WAV is an implementation artifact only. It must be removed:

- after successful TXT/SRT generation;
- when Whisper fails;
- when output validation fails;
- as part of package cleanup after any `Screen2SocialError` raised after package creation.

A successful package must never contain `.transcription.wav`.

## 8. Whisper invocation

Screen2Social invokes the configured `whisper-cli` executable with the configured local model.

The command must request:

```text
language auto
TXT output
SRT output
output base ready/<slug>/transcript
```

The expected final artifacts are therefore:

```text
ready/<slug>/transcript.txt
ready/<slug>/transcript.srt
```

Screen2Social does not parse Whisper stdout to create its own transcription formats. It relies on the engine's native TXT and SRT outputs, then verifies that both expected files exist.

The subprocess is executed without a shell. A non-zero exit code is a transcription failure.

## 9. Error contract

V0.4 adds stable transcription-specific Screen2Social errors.

Required codes:

```text
WHISPER_CLI_NOT_FOUND
WHISPER_MODEL_NOT_FOUND
TRANSCRIPTION_NO_AUDIO
TRANSCRIPTION_FAILED
```

Semantics:

```text
SCREEN2SOCIAL_WHISPER_CLI missing/empty/invalid file -> WHISPER_CLI_NOT_FOUND
SCREEN2SOCIAL_WHISPER_MODEL missing/empty/invalid file -> WHISPER_MODEL_NOT_FOUND
source has no audio and transcription requested -> TRANSCRIPTION_NO_AUDIO
FFmpeg audio extraction failure -> TRANSCRIPTION_FAILED
whisper-cli non-zero exit -> TRANSCRIPTION_FAILED
expected transcript.txt missing -> TRANSCRIPTION_FAILED
expected transcript.srt missing -> TRANSCRIPTION_FAILED
other transcription execution/output failures -> TRANSCRIPTION_FAILED
```

These errors inherit from `Screen2SocialError` so the existing CLI formatting remains valid:

```text
<ERROR_CODE>: <message>
```

The source video is never deleted, overwritten, or modified.

## 10. Fail-fast and fail-closed behavior

The pipeline order is:

```text
1. resolve source path
2. discover mandatory FFmpeg/ffprobe toolchain
3. probe source media
4. if transcribe:
     a. verify source has audio
     b. discover/validate whisper-cli
     c. discover/validate model
5. create ready/<slug>/
6. transcode linkedin.mp4
7. probe linkedin.mp4
8. create thumbnail.png
9. if transcribe:
     a. extract .transcription.wav
     b. run whisper-cli with language=auto
     c. verify transcript.txt
     d. verify transcript.srt
     e. delete .transcription.wav
10. create metadata.json
11. create post.md
12. return ProcessResult
13. CLI prints READY: <package_dir>
```

Configuration and no-audio errors therefore fail before the package directory is created.

If a `Screen2SocialError` occurs after package creation, `process_recording()` continues to remove the complete package directory before re-raising. This preserves the existing invariant that `READY:` means the entire requested package exists.

No partial four-file V0.3 package may be retained after a requested transcription fails.

## 11. `process_recording()` contract

Conceptually the orchestrator becomes:

```python
process_recording(
    source,
    *,
    ready_root=Path("ready"),
    toolchain=None,
    transcribe=False,
)
```

`transcribe=False` is the compatibility default.

`ProcessResult` gains optional transcription paths:

```python
transcript_path: Path | None
subtitle_path: Path | None
```

When `transcribe=False`, both are `None`.

When `transcribe=True` and processing succeeds:

```text
transcript_path -> ready/<slug>/transcript.txt
subtitle_path   -> ready/<slug>/transcript.srt
```

Existing result fields remain unchanged.

## 12. CLI contract

The only new public CLI surface in V0.4 is:

```powershell
screen2social process demo.mkv --transcribe
```

Successful stdout remains exactly:

```text
READY: <package_dir>
```

Screen2Social does not print the recognized text, subtitle content, model path, Whisper path, or additional successful-output lines.

On failure the existing one-line error style remains:

```text
<ERROR_CODE>: <message>
```

No standalone `screen2social transcribe` command is added in V0.4.

## 13. Metadata contract

Without transcription, metadata must remain semantically identical to V0.3:

```json
"steps": [
  "linkedin_transcode",
  "thumbnail",
  "post_template"
]
```

With successful transcription:

```json
"steps": [
  "linkedin_transcode",
  "thumbnail",
  "post_template",
  "transcription"
]
```

and metadata additionally contains:

```json
"transcription": {
  "engine": "whisper.cpp",
  "language": "auto",
  "text_file": "transcript.txt",
  "subtitle_file": "transcript.srt"
}
```

The metadata does not record:

- the absolute local model path;
- the absolute `whisper-cli` path;
- model download URLs;
- guessed detected language.

V0.4 does not parse Whisper output solely to populate `detected_language`.

## 14. `doctor` behavior

`screen2social doctor` remains unchanged in V0.4 and continues to validate only the mandatory FFmpeg and ffprobe dependencies.

Whisper configuration is validated on demand when `--transcribe` is used.

A possible future command such as `screen2social doctor --transcription` is explicitly deferred until real usage demonstrates diagnostic pain.

## 15. Dependency policy

V0.4 must not add Whisper, PyTorch, faster-whisper, model download libraries, HTTP clients, or other transcription runtimes to Python package dependencies.

The Python runtime dependency policy remains lightweight. `whisper.cpp` is an external local executable analogous to FFmpeg from the application's perspective, but optional rather than mandatory.

The existing `simpleobsws` dependency remains unrelated to transcription.

## 16. Testing strategy

Tests must not download or execute a real Whisper model in CI.

### `tests/test_transcription.py`

Cover at minimum:

- configuration discovery with valid environment variables;
- missing CLI environment configuration;
- CLI path that does not resolve to a file;
- missing model environment configuration;
- model path that does not resolve to a file;
- deterministic FFmpeg temporary-audio command construction;
- temporary-audio extraction success/failure mapping;
- deterministic Whisper command construction;
- command contains language `auto`;
- command requests TXT and SRT output;
- command uses `transcript` as output base;
- non-zero Whisper exit maps to `TRANSCRIPTION_FAILED`;
- missing TXT maps to `TRANSCRIPTION_FAILED`;
- missing SRT maps to `TRANSCRIPTION_FAILED`;
- successful transcription returns both expected paths;
- temporary WAV is removed on success;
- transcription-specific temporary artifacts are not leaked on failure.

### `tests/test_package.py`

Cover at minimum:

- default `transcribe=False` retains the V0.3 four-file package;
- Whisper configuration is not discovered when `transcribe=False`;
- no-audio source with `transcribe=True` fails before package creation;
- invalid Whisper configuration fails before package creation;
- successful `transcribe=True` produces exactly the expected six package artifacts plus no temporary WAV;
- `ProcessResult` contains optional transcript/subtitle paths correctly;
- transcription failure after package creation removes the whole package;
- source file survives all failure cases unchanged.

### `tests/test_metadata.py`

Cover at minimum:

- V0.3 metadata shape/steps remain unchanged without transcription;
- transcription-enabled metadata adds `transcription` to steps;
- transcription block has exactly engine/language/text/subtitle fields required by this design;
- absolute local Whisper/model paths are absent.

### `tests/test_cli.py`

Cover at minimum:

- parser accepts `process <input> --transcribe`;
- parser default remains non-transcribing;
- CLI forwards the boolean to `process_recording()`;
- successful stdout remains exactly one `READY:` line;
- transcription errors preserve `<CODE>: <message>` formatting.

### CI fake engine

CI uses a controlled fake Whisper executable or injected subprocess boundary that creates deterministic `.txt` and `.srt` files. No model is downloaded. No network is required.

The fake must exercise Screen2Social's command/output/error contract rather than duplicate Whisper internals.

## 17. Real Windows smoke acceptance

Before feature merge, perform a real Windows smoke using an actual local `whisper-cli`, local model, FFmpeg, and a real recording containing speech.

Example:

```powershell
screen2social process "A:\path\to\demo.mkv" --transcribe
```

Verify:

```text
linkedin.mp4          exists
thumbnail.png         exists
metadata.json         exists
post.md               exists
transcript.txt        exists
transcript.srt        exists
.transcription.wav    does not exist
```

Also verify manually:

- `transcript.txt` is readable UTF-8 text;
- `transcript.srt` contains valid-looking numbered subtitle entries and timestamps;
- recognized content substantially corresponds to the spoken demo;
- source recording still exists and was not modified;
- rerunning into the same `ready/<slug>/` still fails with the existing `OUTPUT_EXISTS` behavior;
- successful CLI output remains `READY: <package_dir>`.

The smoke result is evidence for Windows integration only; automated tests remain responsible for deterministic contract coverage.

## 18. Acceptance criteria

V0.4 feature work is ready for review when all of the following are true:

```text
[ ] default process flow remains compatible with V0.3
[ ] --transcribe is opt-in
[ ] no Whisper configuration is required without --transcribe
[ ] whisper-cli and model are external/local and never downloaded by Screen2Social
[ ] language is auto
[ ] source without audio returns TRANSCRIPTION_NO_AUDIO
[ ] successful transcription package has transcript.txt and transcript.srt
[ ] successful package has no temporary WAV
[ ] failures after package creation remove the whole package
[ ] failures never modify/delete source recording
[ ] metadata truthfully records transcription only when performed
[ ] successful CLI stdout remains one READY line
[ ] CI requires no real Whisper model or network
[ ] full automated suite passes
[ ] real Windows smoke passes
[ ] final diff review has no blocking findings
```

Feature merge requires explicit human approval after tests, CI, smoke, and review.

The `0.4.0` package/runtime version bump is not part of this feature branch and must use a separate release gate after the feature is merged.

## 20. Design rationale

The design deliberately keeps V0.4 narrow.

The main value is not simply speech-to-text. It is adding a reusable textual representation of a recorded demo while preserving Screen2Social's existing invariants:

- local-first;
- zero paid API requirement;
- explicit user control;
- deterministic package shape;
- source safety;
- no partial-success ambiguity;
- minimal Python dependency growth;
- isolated components with clear responsibilities.

`transcript.txt` immediately supports reading, copying, searching, and future post drafting. `transcript.srt` preserves timed segments for future subtitle workflows without committing V0.4 to video editing. The external `whisper.cpp` boundary prevents a local transcription feature from turning the base Python package into a heavyweight ML runtime.
